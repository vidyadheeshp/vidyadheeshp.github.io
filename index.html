वाक्

a Sanskrit-native programming language

Sanskrit does not decide meaning by word order. It marks the role each participant plays in an action — and Vāk makes those roles a type system.

Pāṇini analysed a sentence by kāraka: who acts, what is acted upon, by what means, from what source. Vāk lets a function's parameters declare those same roles, and then checks the grammar of your function the way Pāṇini checked the grammar of a sentence. Because the roles are marked, the arguments carry their own labels and the order stops mattering — exactly the freedom that case endings give a Sanskrit sentence.

वाक् Vāk

Every stage of its front end — lexer, parser, analyser, compiler and virtual machine — is written in Vāk itself.

# संग्रहः is the अपादानम् — what we draw *from*.
# परीक्षा is the करणम् — the means *by which*.
कार्यम् छानय(अपादानम् सूची संग्रहः, करणम् कार्यम् परीक्षा) : सूची {
    सूची फलम् = []।
    प्रत्येकम् (अङ्गम् अन्तः संग्रहः) {
        यदि (परीक्षा(अङ्गम्)) { योजय(फलम्, अङ्गम्)। }
    }
    प्रत्यागच्छ फलम्।
}

# तीनों एक ही आह्वान — the order is free because the roles are marked.
मुद्रय छानय(अङ्काः, समः)।
मुद्रय छानय(अपादानम्: अङ्काः, करणम्: समः)।
मुद्रय छानय(करणम्: समः, अपादानम्: अङ्काः)।
Run it in your browser → About the language The manual Source

A Vāk program can be executed by five different engines — a tree-walking interpreter, a bytecode virtual machine, that machine written in Vāk, a machine in C, and the whole self-hosted toolchain compiled to a native executable. All five are held to byte-identical output on every example, which is what keeps the claim honest. The playground above is that same toolchain compiled to WebAssembly: it lexes, parses, analyses, compiles and runs Vāk inside the browser, with no server involved.

परिचयः

about

I hold an MTech in Software Engineering from MIT Manipal and a bachelor's degree from Visvesvaraya Technological University. Before teaching, I worked as a Junior Software Engineer at Leviosa Consulting Pvt Ltd on ERP development, deployment and maintenance.

My research is in cybersecurity. My teaching runs through programming languages and robotic process automation; what I build runs through web and application development, machine learning and natural language processing. Alongside them I read Indian philosophy — particularly Dvaita epistemology and tarka, the classical logic tradition.

What holds those together is a conviction that Sanskrit belongs in technology rather than beside it. It is usually invoked ceremonially in computing — a quotation at the top of a paper, a claim about its suitability for machines, and nothing built. I wanted to find out what it costs to actually do it.

The two halves are less separate than they look. Pāṇini's Aṣṭādhyāyī is a formal grammar with rule ordering and metarules, written twenty-five centuries before anyone spoke of parsers; the tarka literature is a theory of valid inference. Vāk is what happens when you take that seriously enough to compile it — and it turns out to make a rather good teaching language, because a student who can read the keywords can often guess what a program means.
